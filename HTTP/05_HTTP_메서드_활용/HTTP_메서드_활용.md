# HTTP 메서드 활용

## 클라이언트에서 서버로 데이터를 전송하는 방법 2가지

- **쿼리 파라미터를 통한 데이터 전송**
  - GET
  - 주로 정렬, 필터(검색어)에 사용
- **메시지 바디를 통한 데이터 전송**
  - POST, PUT, PATCH
  - 회원가입, 상품 주문, 리소스 등록, 리소스 변경 등에 사용

## 클라이언트에서 서버로 데이터 전송하는 4가지 상황

### 1. 정적 데이터 조회 (이미지, 정적 텍스트 문서)

- 조회는 **GET** 메서드를 사용한다.
- 정적 데이터는 일반적으로 쿼리 파라미터 없이 **리소스 경로만으로 단순 조회**가 가능하다.

### 2. 동적 데이터 조회 (쿼리 파라미터 사용)

- 같은 리소스를 조회하더라도 사용자가 전달한 조건에 따라 결과가 달라지는 경우.
- 예) 게시판 100개 중 검색어 "자바", 정렬 "최신순"으로 요청하면 → `GET /posts?keyword=자바&sort=latest`
- 주로 검색, 게시판 목록의 정렬/필터(검색어)에 사용된다.
- 조회 조건을 좁히는 필터, 결과를 정렬하는 조건에 주로 쓰인다.
- 조회는 GET을 사용하고, GET은 **쿼리 파라미터**로 데이터를 전달한다.

### 3. HTML Form 데이터 전송

- HTML Form은 **GET과 POST** 방식의 데이터 전송을 지원한다.
- 기본적으로 POST 방식 전송 시 `Content-Type: application/x-www-form-urlencoded`를 사용한다.
  - Form 데이터를 메시지 바디에 `key=value` 형태로 담아 전송하며, URL 인코딩해서 전달한다.
  - 예) 한글 등의 문자는 URL 인코딩되어 전송된다. `abc김` → `abc%EA%B9%80`
- GET 방식으로 Form 데이터를 전송할 수도 있으며, 이 경우 데이터가 URL의 **쿼리 파라미터**
  (`?username=kim&age=20`)로 전달되어 조회에 사용된다.
- 파일 같은 바이너리 데이터를 Form 데이터와 함께 전송해야 할 때는
  `Content-Type: multipart/form-data`를 사용한다.
  여러 종류의 데이터를 각각 구분해서 전송할 수 있어 **파일 업로드**와 같은 상황에서 사용한다.

### 4. HTTP API 데이터 전송

- HTTP API는 서버-서버, 앱-서버, 웹-서버 등에서 HTTP 요청을 직접 만들어 데이터를 주고받는 방식이다.
- 예) React에서 HTTP 요청을 보내면 Spring 서버가 데이터를 받아 작업을 처리한다.

데이터 전송 방법:

- **POST, PUT, PATCH**: 메시지 바디에 데이터를 담아 전송
- **GET**: 조회 목적, 쿼리 파라미터로 데이터 전달

`Content-Type: application/json`은 메시지 바디의 데이터가 어떤 형식인지 서버에게 알려주는 헤더다.
서버는 메시지 바디에 들어온 데이터가 어떤 형식인지 알아야 하기 때문에 이 헤더가 필요하다.

# HTTP API 설계 예시

## POST 기반 등록 vs PUT 기반 등록

### POST 기반 등록 = 컬렉션 (Collection)

클라이언트가 리소스의 URI를 모르고, 서버가 URI를 생성하고 관리한다.

```
클라이언트 -> POST /members 요청
서버 -> 회원 생성, /members/100 생성 완료
서버 -> 클라이언트에게 응답
```

### PUT 기반 등록 = 스토어 (Store)

클라이언트가 리소스의 URI를 직접 알고, 그 위치에 저장/대체한다.

```
클라이언트 -> PUT /files/star.jpg 요청
클라이언트가 직접 정한 URI 위치에 저장
```

### 정리

- **POST**: 클라이언트가 리소스의 URI를 모르고 서버에 요청하면, 서버가 URI를 생성하고 관리한다.
- **PUT**: 클라이언트가 리소스의 URI를 직접 정해서, 해당 URI에 리소스를 저장하거나 대체한다.

# HTML FORM 사용

- HTML FORM은 **GET, POST만 지원**한다.
- GET, POST만 지원하기 때문에 제약이 있다. (AJAX 같은 기술로 이 제약을 해결할 수도 있다)
- 이런 제약을 해결하기 위해 **동사로 된 리소스 경로**를 사용하기도 하는데, 이를 **컨트롤 URI**라고 한다.

## 컨트롤 URI

- 예) POST의 `/new`, `/edit`, `/delete` 같은 경로가 컨트롤 URI다.
- HTTP 메서드만으로 표현하기 애매한 경우에 사용한다. (HTTP API에서도 마찬가지)
