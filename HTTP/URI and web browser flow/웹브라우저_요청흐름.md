# 웹 브라우저 요청 흐름

웹 브라우저에서 `www.google.com`에 접속할 때, 실제로 내부에서는 어떤 과정을 거치는지 정리한다.

## 1. DNS 조회

- 웹 브라우저에서 접속을 시도하면 먼저 **DNS**를 조회해서 도메인 명(`www.google.com`)을
  실제 IP 주소(예: `200.200.200.2`)로 변환한다.

## 2. HTTP 요청 메시지 생성

DNS로 IP를 알아낸 뒤, 웹 브라우저는 HTTP 요청 메시지를 생성한다.

```
GET /search?q=hello&hl=ko HTTP/1.1
Host: www.google.com
```

## 3. 소켓 라이브러리를 통한 전달

웹 브라우저가 만든 HTTP 메시지는 **SOCKET 라이브러리**를 통해 전달된다.
이때 소켓 라이브러리가 담당하는 일은 크게 두 가지다.

- **A. TCP/IP 연결** : 목적지 IP, PORT로 TCP 연결을 맺는다 (3-way handshake 포함)
- **B. 데이터 전달** : 연결된 TCP 위에 실제 데이터(HTTP 메시지)를 실어 보낸다

> 즉 "handshake가 끝난 뒤 소켓 라이브러리로 전달"되는 게 아니라,
> **소켓 라이브러리 자체가 TCP 연결(handshake)과 데이터 전달을 모두 담당**한다.

## 4. TCP/IP 패킷 생성

소켓 라이브러리를 거친 데이터는 TCP/IP 계층에서 패킷으로 감싸진다.

- TCP/IP 패킷 안에는 출발지 IP/PORT, 목적지 IP/PORT 등의 정보가 들어간다.
- 그 안에 **HTTP 메시지(요청 데이터)** 가 포함되어 전송된다.

```
[ TCP/IP 패킷 ]
  출발지 IP, PORT
  목적지 IP, PORT
  ...
  [ HTTP 메시지 ]
    GET /search?q=hello&hl=ko HTTP/1.1
    Host: www.google.com
```

## 5. 패킷 전송 및 서버 도착

- 클라이언트(웹 브라우저, IP: `100.100.100.1`)가 패킷을 전송하면
  네트워크를 거쳐 서버(구글 서버, IP: `200.200.200.2`)에 도착한다.

## 6. 서버의 응답 메시지 생성

서버는 요청 패킷을 받으면 요청을 처리하고, HTTP 응답 메시지를 생성한다.

```
HTTP/1.1 200 OK
Content-Type: text/html;charset=UTF-8
Content-Length: 3423

<html>
  <body>...</body>
</html>
```

- 상태 라인(`HTTP/1.1 200 OK`), 헤더(`Content-Type`, `Content-Length`), 바디(HTML 문서)로 구성된다.

## 7. 응답 패킷 전송 및 렌더링

- 서버는 응답 메시지를 TCP/IP 패킷으로 감싸서 다시 클라이언트에게 전송한다.
- 웹 브라우저가 응답 패킷을 받으면, 그 안의 HTML 내용을 **렌더링**해서 화면에 보여준다.

## 전체 흐름 요약

```
DNS 조회
  → HTTP 요청 메시지 생성
  → 소켓 라이브러리(TCP 연결 + 데이터 전달)
  → TCP/IP 패킷 생성(HTTP 메시지 포함)
  → 네트워크 전송 → 서버 도착
  → 서버가 요청 처리 후 HTTP 응답 메시지 생성
  → 응답 패킷 전송 → 클라이언트 도착
  → 웹 브라우저가 HTML 렌더링
```
