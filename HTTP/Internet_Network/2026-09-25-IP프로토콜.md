# IP 프로토콜 (Internet Protocol)

## IP 프로토콜의 역할

- 지정한 IP 주소에 데이터를 전달하는 역할을 한다.
- 데이터는 **패킷(Packet)** 이라는 통신 단위로 나뉘어 전달된다.

## IP 패킷 정보

IP 패킷에는 기본적으로 다음 정보가 담긴다.

- 출발지 IP
- 목적지 IP
- 전송 데이터

클라이언트가 패킷을 만들어 전송하면, 네트워크를 거쳐 서버가 이를 수신한다.
(참고: 서버가 받았다는 것을 클라이언트에게 확인시켜주는 응답 처리는 IP 자체의 기능이 아니라,
IP 위에서 동작하는 **TCP**가 담당하는 기능이다. IP는 그저 패킷을 전달만 할 뿐, 잘 도착했는지는 보장하지 않는다.)

## IP 프로토콜의 한계

IP는 패킷을 목적지까지 전달해주는 역할만 할 뿐, 아래와 같은 한계를 가진다.

### 1. 비연결성

- 상대방 서버가 패킷을 받을 수 없는 상태(전원 꺼짐, 서비스 불능 등)여도
  일단 패킷을 전송해버린다.
- 즉, 연결 여부를 확인하지 않고 무조건 전송한다.

### 2. 비신뢰성

- **패킷 소실**: 중간에 패킷이 유실될 수 있다.
- **패킷 순서 문제**: 패킷이 여러 개로 나뉘어 전송될 경우, 순서가 뒤바뀌어 도착할 수 있다.

### 3. 프로그램(포트) 구분 불가

- 같은 IP를 사용하는 서버 내에서 통신하는 애플리케이션이 여러 개일 경우,
  IP만으로는 어떤 애플리케이션에게 전달해야 할지 구분할 수 없다.

## 정리

IP 프로토콜의 이러한 한계들은 상위 프로토콜을 통해 보완된다.

| 한계 | 보완하는 방법 |
|---|---|
| 비연결성, 비신뢰성 | TCP (연결형 프로토콜, 순서 보장·재전송 등) |
| 프로그램(포트) 구분 불가 | PORT 번호 |

다음에는 이 한계를 보완하는 **TCP/UDP**와 **포트(PORT)** 를 정리할 예정.
