# TCP 연결 식별 (출발지/목적지 IP, PORT)

## TCP 연결은 어떻게 구분될까?

TCP 연결(세션)은 다음 4가지 정보의 조합으로 식별된다.

- 출발지 IP
- 출발지 PORT
- 목적지 IP
- 목적지 PORT

이 4가지 값의 조합(4-tuple)이 다르면 서로 다른 연결로 취급된다.

## 클라이언트는 같은 IP로 여러 서버에 요청 가능

클라이언트는 자신의 IP(출발지 IP)는 하나뿐이어도, **목적지 IP/PORT를 다르게** 해서
동시에 여러 서버와 연결을 맺을 수 있다.

예시)

| 출발지 IP | 출발지 PORT | 목적지 IP | 목적지 PORT | 대상 |
|---|---|---|---|---|
| 클라이언트 IP | 50000 | 구글 서버 IP | 443 | 구글 |
| 클라이언트 IP | 50001 | 네이버 서버 IP | 443 | 네이버 |

목적지 IP가 다르기 때문에 4-tuple 조합이 달라져서 동시에 여러 연결이 가능하다.

## 같은 서버에 여러 번 연결할 때는?

같은 서버(같은 목적지 IP, 같은 목적지 PORT)에 연결하는 경우에도,
클라이언트가 **매번 다른 출발지 PORT**를 사용해서 서로 다른 연결로 구분한다.

예) 브라우저에서 같은 사이트의 여러 리소스(이미지, css, js 등)를 동시에 요청할 때,
클라이언트는 요청마다 다른 출발지 PORT를 사용해 여러 개의 TCP 연결을 동시에 유지한다.

## 정리

- 이전에 정리한 IP 프로토콜의 한계 중 "같은 IP를 사용하는 애플리케이션이 여러 개일 때 구분이 안 된다"는
  문제를 **PORT**가 해결해준다.
- 즉, TCP 연결의 식별자는 IP만이 아니라 **IP + PORT의 조합**이다.
