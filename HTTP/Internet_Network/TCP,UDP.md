# TCP, UDP

## 인터넷 프로토콜 스택의 4계층

인터넷 프로토콜은 크게 4계층 구조로 되어 있다.

1. 애플리케이션 계층 (HTTP, FTP 등)
2. 전송(TCP/UDP) 계층
3. 인터넷(IP) 계층
4. 네트워크 인터페이스(LAN) 계층

## 데이터 전송 과정 (캡슐화)

애플리케이션에서 데이터를 생성하면 아래 순서로 캡슐화되어 전송된다.

1. 애플리케이션이 SOCKET 라이브러리를 통해 데이터 전달
2. TCP 정보 생성 (전송하려는 메시지 데이터를 포함)
3. IP 패킷 생성 (TCP 데이터를 포함)
4. LAN 카드를 통해 실제 전송

## TCP의 특징

- **연결지향**: TCP 3-way handshake (가상 연결)
- **데이터 전달 보증**
- **순서 보장**

TCP는 신뢰할 수 있는 프로토콜이며, 현재 대부분의 통신에서 TCP를 사용한다.

### 1. 연결지향 - 3 way handshake

용어 정리

- **SYN**: 연결 요청
- **ACK**: 요청 수락(확인)

과정
<img width="805" height="492" alt="image" src="https://github.com/user-attachments/assets/350d96f3-eb3b-4cb8-a40b-8e0b67f7b519" />



1. 클라이언트 → 서버 : SYN 전송
2. 서버 → 클라이언트 : SYN + ACK 전송
3. 클라이언트 → 서버 : ACK 전송 (여기서 데이터를 함께 실어 보낼 수 있음)

> 보통 "3단계 연결이 끝난 뒤에야 데이터를 보낼 수 있다"고 생각하기 쉽지만,
> 실제로는 **마지막 ACK를 보낼 때 데이터를 함께 전송할 수 있어** 더 효율적이다.

참고: 3 way handshake연결을 해도 데이터를 바로 전송할 수 있는게 아니다. 클라이언트와 서버간 연결만 한 것이다. (추가 작업을 해야야한다)

만약 서버가 꺼져 있는 상태라면, 클라이언트가 SYN을 보내도 응답이 오지 않기 때문에
서버 다운 상태를 감지하고 대처할 수 있다.

### 2. 데이터 전달 보증

클라이언트가 데이터를 전송하면, 서버는 데이터를 잘 받았다는 응답(ACK)을 보내준다.
응답이 없으면 재전송 등으로 전달을 보증한다.

### 3. 순서 보장

클라이언트가 패킷을 1, 2, 3 순서로 보냈는데 서버에 2, 1, 3 순서로 도착했다면,
서버는 클라이언트에게 **1번부터 다시 보내라고 요청**한다.

> 위 특징들(연결지향, 전달 보증, 순서 보장)은 앞서 정리한 IP 프로토콜의 단점(비연결성, 비신뢰성)을 보완해준다.

## UDP (User Datagram Protocol)

- 연결지향 X (3-way handshake 없음)
- 데이터 전달 보증 X
- 순서 보장 X

데이터 전달 및 순서가 보장되지 않지만, 그만큼 **단순하고 빠르다**.

- 기능적으로는 IP와 거의 같고, 여기에 **PORT + 체크섬** 정도만 추가된 수준이다.
- 신뢰성 보장이 빠져 있는 대신, 필요한 기능(순서 보장 등)은 애플리케이션 단에서 직접 구현해야 한다.

## TCP vs UDP 속도 차이

- TCP: 3-way handshake로 연결을 맺는 데 시간이 걸리고, 데이터를 TCP/IP로 감싸는 과정(오버헤드)이 있어 상대적으로 느리다.
- UDP: 연결 과정과 오버헤드가 거의 없어 TCP보다 빠르다. 단, 신뢰성 있는 통신이 필요하면 애플리케이션에서 추가 작업을 해줘야 한다.
