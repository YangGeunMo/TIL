# 스프링 부트 기본 오류 처리 
스프링 부트가 제공하는 `BasicErrorController`를 사용해서 api 예외처리가 가능하다.

```java
@RequestMapping(produces = MediaType.TEXT_HTML_VALUE)
public ModelAndView errorHtml(HttpServletRequest request, HttpServletResponse response) {}

@RequestMapping
public ResponseEntity<Map<String, Object>> error(HttpServletRequest request){}
```

- errorHtml : 클라이언트 요청이 Accept헤더 값이 text/html인 경우 view 제공
- error() : 그 외 경우 ResponseEntity로 HTTP Bodyd에 JSON을 반환

- BasicErrorController는 /error 기본 경로로 받는다. 


~~~java
// 클라이언트의 Accept 헤더가 application/json이면 이 메서드가 호출됨
// produces 조건이 맞으면 스프링이 이 메서드를 선택하고, 반환값을 응답으로 쓸 때 메시지 컨버터를 찾아 사용함
@RequestMapping(value = "/error-page/500", produces = MediaType.APPLICATION_JSON_VALUE)
public ResponseEntity<Map<String, Object>> errorPage500Api(
        HttpServletRequest request) {

    log.info("API errorPage 500");

    // 응답 바디에 담을 데이터
    // 이 Map 자체는 JSON이 아니고, 메시지 컨버터(MappingJackson2HttpMessageConverter)가
    // Accept가 application/json인 것을 확인한 뒤 Jackson으로 JSON 문자열로 변환함
    Map<String, Object> result = new HashMap<>();

    // 오류가 발생할 때 서블릿 컨테이너가 request에 저장해 둔 예외 객체를 꺼냄
    Exception ex = (Exception) request.getAttribute(ERROR_EXCEPTION);

    // 오류 상태 코드를 바디에도 넣음 (Object 타입 그대로 저장)
    result.put("status", request.getAttribute(ERROR_STATUS_CODE));

    // 예외 메시지를 바디에 넣음
    // ex가 null이면 여기서 NullPointerException 발생
    result.put("message", ex.getMessage());

    // HTTP 응답 상태 코드를 설정하기 위해 오류 코드를 Integer로 꺼냄
    Integer statusCode = (Integer) request.getAttribute(RequestDispatcher.ERROR_STATUS_CODE);

    // ResponseEntity는 바디, 상태 코드, 헤더를 담는 그릇
    // 바디(Map) → 메시지 컨버터가 JSON으로 변환, 상태 코드(statusCode) → HTTP 응답 라인에 설정
    // statusCode가 null이면 HttpStatus.valueOf에서 예외 발생
    return new ResponseEntity<>(result, HttpStatus.valueOf(statusCode));
}
~~~

구현한 코드를 스프링 부트는 BasicErrorController에서 error()가 기본 오류 응답(JSON Map)을 만들어 주고, 직접 만든 오류 메서드는 그 형식을 바꾸고 싶을 때 쓴다.

#### HTML 페이지 vs API 오류


- BasicErrorController는 html페이지를 제공하는데 매우 편리하다. 4xx, 5xx 등을 처리해준다. 
- api 오류처리는 api, 예외, 컨트롤러마다 다른 응답 결과를 출력해야할 수도 있다. (회원관련과 상품관련의 예외가 발생할때 응답이 다르다) 
- html 화면 처리는 BasicErrorController를 사용하고 api 오류 처리는 @ExceptionHandler 를 사용하자.
