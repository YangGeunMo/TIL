# 프론트 컨트롤러 - V5

## 유연한 컨트롤러

* 어떤 개발자는 V3, 어떤 개발자는 V4 방식으로 개발하고 싶다면 어떻게 해야 하나
* 지금까지 개발한 프론트 컨트롤러는 하나의 인터페이스만 사용할 수 있었는데 V3,V4 다른 인터페이스므로 호환이 안된다. 
* 어댑터 패턴을 사용해서 프론트 컨트롤러가 많은 컨트롤러를 처리할 수 있다.

#### 핸드러 어댑터
* 중간에 어댑터 역할을 하는 어댑터가 추가 되었는데 이름이 핸드러 어댑터이다. 이 어댑터가 있어 다양한 컨트롤러를 호출할 수 있다.

#### 핸들러
* 컨트롤러 이름을 더 넓은 범위인 핸들러로 변경. 어댑터가 있기에 컨트롤러 개념 뿐 아니라 어떠한 것이든 해당하는 종류의 어댑터만 있으면 다 처리할 수 있기 때문이다. 



### MyHandlerAdapter
어댑터를 이렇게 구현해야 한다는 어댑터 인터페이스

```java
public interface MyHandlerAdapter {

    //handler는 컨트롤러를 의미
    // 어댑터가 해당 컨트롤러를 처리할 수 있는지 판단하는 메서드
    boolean supports(Object handler);

    //컨트롤러를 호출하고 결과로 ModelView를 반환
    ModelView handle(HttpServletRequest request, HttpServletResponse response,Object handler) throws SecurityException, IOException;
}
```

* 어댑터는 실제 컨트롤러를 호출하고, 그 결과로 ModelView를 반환해야 한다.
* 실제 컨트롤러가 ModelView를 반환하지 못하면, 어댑터가 ModelView를 직접 생성해서라도 반환해야
한다.
* 이전에는 프론트 컨트롤러가 실제 컨트롤러를 호출했지만 이제는 이 어댑터를 통해서 실제 컨트롤러가 호출
된다.

### 프론트 컨트롤러 - V5
```java
@WebServlet(name = "frontControllerServletV5", urlPatterns = "/front-controller/v5/*")
public class FrontControllerServletV5 extends HttpServlet {

    //매핑 정보 값을 아무 값이나 받을 수 있는 Object로 변겨
    private final Map<String, Object> handlerMappingMap = new HashMap<>();
    private final List<MyHandlerAdapter> handlerAdapters = new ArrayList<>();

    // WAS가 시작되면서 Servlet이 초기화될 때 기본 생성자 실행되고 Map에 key, value로 저장된다.
    public FrontControllerServletV5() {
        initHandlerMappingMap(); //핸들러 매핑 초기화
        initHandlerAdapters(); // 어댑터 초기화
    }

    private void initHandlerMappingMap() {
        handlerMappingMap.put("/front-controller/v5/v3/members/new-form", new MemberFormControllerV3());
        handlerMappingMap.put("/front-controller/v5/v3/members/save", new MemberSaveControllerV3());
        handlerMappingMap.put("/front-controller/v5/v3/members", new MemberListControllerV3());

        handlerMappingMap.put("/front-controller/v5/v4/members/new-form", new MemberFormControllerV4());
        handlerMappingMap.put("/front-controller/v5/v4/members/save", new MemberSaveControllerV4());
        handlerMappingMap.put("/front-controller/v5/v4/members", new MemberListControllerV4());
    }

    private void initHandlerAdapters() {
        handlerAdapters.add(new ControllerV3HandlerAdapter());
        handlerAdapters.add(new ControllerV4HandlerAdapter());
    }

    @Override
    protected void service(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {

        //요청이 왔을 때 예시) front-controller/v5/v3/members/save
        //URL 요청하면 -> 컨트롤러 반환
        //1. 핸들러 조회 : 요청 URL에 맞는 Controller 찾기
        //MemberSaveControllerV3() 참조값
        Object handler = getHandler(request);

        if (handler == null) {
            response.setStatus(HttpServletResponse.SC_NOT_FOUND);
            return;
        }
        //2. 핸들러 처리 어댑터 조회 true면 ControllerV3HandlerAdapter() 참조값 반환
        MyHandlerAdapter adapter = getHandlerAdapter(handler);

        //3. handler(handler) 호출
        //4. Handler 호출 ( adapter 내부에서 controller.process() 실행
        //5. ModelView 반환
        //요청받은 request, response, //MemberSaveControllerV3() 참조값 전달
        ModelView mv = adapter.handle(request, response, handler);
        // 논리 이름 save-result 변수에 저장
        String viewName = mv.getViewName();
        //6. viewResolver 호출
        //7. "/WEB-INF/views/save-result .jsp" 물리 뷰 반환
        MyView view = viewResolver(viewName);
        //8. render(model) 호출
        view.render(mv.getModel(),request,response);
    }
    //2. 핸들러를 처리할 수 있는 핸들러 어댑터 조회
    private MyHandlerAdapter getHandlerAdapter(Object handler) {
        // 각 adapter의 supports()로 handler 타입 확인, 타입이 같으면 같은 객체 반환 
        for (MyHandlerAdapter adapter : handlerAdapters) {
            if (adapter.supports(handler)) {
                return adapter;
            }
        }
        throw new IllegalArgumentException("handler adapter를 찾을 수없습니다ㅣ handler=" + handler);
    }

    //요청한 URL의 맞는 컨트롤러 객체 반환
    private Object getHandler(HttpServletRequest request) {
        String requestURI = request.getRequestURI();
        return handlerMappingMap.get(requestURI);
    }

    private static MyView viewResolver(String viewName) {
        return new MyView("/WEB-INF/views/" + viewName + ".jsp");
    }
}

```

### ControllerV3HandlerAdapter

```java
public class ControllerV3HandlerAdapter implements MyHandlerAdapter {
    // 타입이 ControllerV3아니면 false, 맞으면 true
    //ControllerV3 타입  MemberSaveControllerV3() : true
    @Override
    public boolean supports(Object handler) {
        return (handler instanceof ControllerV3);
    }

    //request, response, //MemberSaveControllerV3() 참조값 전달 받음
    @Override
    public ModelView handle(HttpServletRequest request, HttpServletResponse response, Object handler) throws SecurityException, IOException {

        //Object 타입이므로 다운캐스팅, MemberSaveControllerV3() 참조값
        ControllerV3 controller = (ControllerV3) handler;
        //username,age 파라미터 값 Map에 저장
        Map<String, String> paramMap = createParamMap(request);
        //4. 핸들러 호출
        ModelView mv = controller.process(paramMap);
        //5. ModelView 반환 save-result
        return mv;
    }

    // 요청받은 파라미터를 Map에 저장한다
    private static Map<String, String> createParamMap(HttpServletRequest request) {
        Map<String, String> paramMap = new HashMap<>();
        // 요청의 모든 파라미터 이름을 가져와서
        // 각 파라미터의 이름과 값을 Map에 저장한다
        request.getParameterNames().asIterator()
                .forEachRemaining(paramName -> paramMap.put(paramName, request.getParameter(paramName)));
        return paramMap;
    }
}
```

### ControllerV4HandlerAdapter

```java
public class ControllerV4HandlerAdapter implements MyHandlerAdapter {

    @Override
    public boolean supports(Object handler) {
        // handler가 ControllerV4 타입이면 true, 아니면 false
        return (handler instanceof ControllerV4);
    }

    @Override
    public ModelView handle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws SecurityException, IOException {

        // Object 타입의 handler를 ControllerV4로 다운캐스팅
        ControllerV4 controller = (ControllerV4) handler;

        // 요청 파라미터를 Map으로 변환
        Map<String, String> paramMap = createParamMap(request);

        // 데이터를 저장할 model 생성
        HashMap<String, Object> model = new HashMap<>();

        // ControllerV4 호출
        // controller가 paramMap에서 데이터를 꺼내고
        // model에 데이터를 저장한 후 뷰 이름만 반환
        String viewName = controller.process(paramMap, model);

        // ModelView 객체 생성 (뷰 이름 저장)
        ModelView mv = new ModelView(viewName);

        // Model 데이터를 ModelView에 저장
        mv.setModel(model);

        return mv;
    }

    // 요청받은 파라미터를 Map에 저장한다
    private static Map<String, String> createParamMap(HttpServletRequest request) {
        Map<String, String> paramMap = new HashMap<>();

        // 요청의 모든 파라미터 이름을 가져와서
        // 각 파라미터의 이름과 값을 Map에 저장한다
        request.getParameterNames().asIterator()
                .forEachRemaining(paramName -> paramMap.put(paramName, request.getParameter(paramName)));

        return paramMap;
    }
}
```

## 정리

### V1: 프론트 컨트롤러 도입

문제: 각 클라이언트가 어떤 Controller를 호출할지 알아야 함

해결:
- FrontController가 모든 요청을 받음
- URL 매핑으로 올바른 Controller 호출
- 다형성(ControllerV1 인터페이스)으로 통일

남은 문제: forward 코드 중복

--- 

### V2: View 분리
문제: 모든 Controller에서 forward 코드 반복

해결:
- MyView 클래스 도입
- Controller는 경로만 반환
- FrontController에서 한 곳에서만 forward 처리

남은 문제: HttpServletRequest, Response에 의존

---

### V3: Model 추가
문제: Controller가 Servlet 기술에 의존적

해결:
- 요청 파라미터를 Map으로 변환
- Model을 별도 객체로 분리
- Controller는 순수 자바 로직만 유지
- View 이름을 논리명/물리명으로 분리 (viewResolver)

남은 문제: Controller가 복잡한 ModelView 객체 생성

---

### V4: 단순한 인터페이스
문제: V3의 기능은 좋지만 구현이 복잡

해결:
- FrontController에서 model을 미리 생성
- Controller는 Map과 String만 다룸
- 더 간단하고 실용적인 인터페이스 제공

특징: V3와 동일한 기능, 더 간단한 구현

---

### V5: 어댑터 도입 (확장성)
문제: V1, V2, V3, V4 등 다양한 버전을 모두 지원하려면?

해결:
- MyHandlerAdapter 인터페이스 도입
- 각 버전별로 HandlerAdapter 구현
- FrontController는 Handler를 Object로 받음
- supports()로 맞는 adapter 찾기
- handle()로 통일된 방식으로 처리

장점:
- 기존 구조 유지하면서 확장 가능
- 새로운 Controller 타입 추가 용이

---

## 핵심 설계 원칙

인터페이스로 추상화

   → 다형성 활용 (V1의 ControllerV1, V2의 ControllerV2)

역할 분리

   → Controller: 비즈니스 로직
   → View: 렌더링
   → Adapter: 호환성 유지

어댑터 패턴

   → 서로 다른 타입을 통일된 방식으로 처리
   → 새로운 기능 추가 시 기존 코드 수정 불필요

점진적 리팩토링

   → 기존 기능 유지하면서 단계적으로 개선
   → 사용자에게 영향 없음
