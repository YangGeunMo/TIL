# 프론트 컨트롤러 - V2

## View 분리

### V1의 문제 

V1의 모든 컨트롤러를 보면 View로 이동하는 부분에 중복 코드가 있다.

```
String viewPath = "/WEB-INF/views/save-result.jsp";
RequestDispatcher dispatcher = request.getRequestDispatcher(viewPath);
dispatcher.forward(request, response);
```

이 부분을 분리해서 별도의 객체로 만들어 중복을 제거한다.

MyView 클래스 
```
public class MyView {

    private String viewPath; // "WEB-INF/views/new-form.jsp"

    public MyView(String viewPath) {
        this.viewPath = viewPath;
    }


    public void render(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
       
        RequestDispatcher dispatcher = request.getRequestDispatcher(viewPath);
		// viewPath에 해당하는 JSP로 forward한다
        // request: 클라이언트 요청 정보 + setAttribute로 저장한 데이터
        // response: 비어있음 (JSP에서 HTML을 작성해서 담음)
        dispatcher.forward(request, response);
    }
}
```

#### ControllerV2
```
/**
 * ControllerV2 인터페이스
 * 반환 타입을 MyView로 한 이유:
 * - 로직이 다 끝난 후 어떤 JSP로 이동할지를 결정
 * - MyView 객체에 경로 정보를 담아서 FrontController에게 전달
 * - forward 코드 중복 제거 (MyView에 통일)
 */
public interface ControllerV2 {
    MyView process(HttpServletRequest request, HttpServletResponse response) 
            throws ServletException, IOException;
}
```

#### 회원 등록 컨트롤러 - V2
```
public class MemberFormControllerV2 implements ControllerV2 {

    @Override
    public MyView process(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
        return new MyView("/WEB-INF/views/new-form.jsp");
    }
}
```

#### 회원 저장 컨트롤러 - V2
```
//회원 저장 컨트롤러 V2
public class MemberSaveControllerV2 implements ControllerV2 {

    private MemberRepository memberRepository = MemberRepository.getInstance();

    @Override
    public MyView process(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {

        // 요청 파라미터에서 username과 age를 가져와 변수에 저장
        String username = request.getParameter("username");
        int age = Integer.parseInt(request.getParameter("age"));

        // 비즈니스 로직: Member 객체 생성 및 저장
        Member member = new Member(username, age);
        memberRepository.save(member);

        // Model에 데이터를 보관한다
        // request.setAttribute로 저장된 데이터를 JSP에서 getAttribute로 꺼낼 수 있다
        request.setAttribute("member", member);

        // MyView 객체를 반환한다
        // 이제 FrontController에서 view.render()로 JSP로 forward한다
        // (V1과 달리 Controller에서 forward하지 않음)
        return new MyView("/WEB-INF/views/save-result.jsp");

    }
}
```

#### 회원 목록 컨트롤러 - V2
```
//회원 목록 조회 컨트롤러 V2
public class MemberListControllerV2 implements ControllerV2 {
    
    private MemberRepository memberRepository = MemberRepository.getInstance();

    @Override
    public MyView process(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {

        // 저장소에서 모든 회원을 조회한다
        List<Member> members = memberRepository.findAll();
        
        // Model에 데이터를 보관한다
        // request.setAttribute로 저장된 데이터를 JSP에서 getAttribute로 꺼낼 수 있다
        request.setAttribute("members", members);
        
        // MyView 객체를 반환한다
        // forward 코드는 FrontController에서 view.render()로 처리한다
        return new MyView("/WEB-INF/views/members.jsp");
    }
}
```

* V1에서 중복이였던 dispatcher.forward()를 각 컨트롤러에서 호출하지 않아도 된다. MyView 객체를 생성하고 뷰 경로만 반환하면 된다. 

#### 프론트 컨트롤러 - V2
```
// /front-controller/v2/* 하위의 모든 요청을 처리한다
@WebServlet(name = "fronControllerServletV2", urlPatterns = "/front-controller/v2/*")
public class FronControllerServletV2 extends HttpServlet {
    
    // URL과 Controller를 매핑해서 저장하는 자료구조
    private Map<String, ControllerV2> controllerMap = new HashMap<>();
    
    // WAS가 시작되면서 Servlet이 초기화될 때 기본 생성자 실행되고 
    // controllerMap에 URL과 Controller를 매핑해서 저장한다
    public FronControllerServletV2() {
        controllerMap.put("/front-controller/v2/members/new-form", new MemberFormControllerV2());
        controllerMap.put("/front-controller/v2/members/save", new MemberSaveControllerV2());
        controllerMap.put("/front-controller/v2/members", new MemberListControllerV2());
    }

    @Override
    protected void service(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {

        // 클라이언트가 요청한 URL을 가져온다
        String requestURI = request.getRequestURI();
        
        // 요청 URL에 맞는 Controller를 찾는다 (다형성의 핵심)
        // ControllerV2 인터페이스로 통일하면 모든 구현체를 같은 타입으로 처리 가능
        ControllerV2 controller = controllerMap.get(requestURI);
        
        // 해당하는 Controller가 없으면 404 에러
        if (controller == null) {
            response.setStatus(HttpServletResponse.SC_NOT_FOUND);
            return;
        }

        // Controller를 호출한다
        // Controller에서 MyView 객체를 반환받는다 (V1과의 차이점)
        // request: 클라이언트 요청 정보 담겨 있음
        // response: 비어있음 (JSP에서 HTML을 작성해서 담음)
        MyView view = controller.process(request, response);
        
        // V2의 개선점: forward 코드가 FrontController에서 한 곳에만 있다!
        // request: 클라이언트 요청 정보 + controller에서 setAttribute로 저장한 데이터
        // response: 비어있음 (JSP에서 HTML을 작성해서 담음)
        // "같은 request 객체가 계속 이동하면서 데이터가 누적된다"
        view.render(request, response);
    }
}
```

* render 메서드를 이용해 경로 정보를 이용해서 rqeust와 response를 JSP로 전달한다.
* V1에서 모든 컨트롤러에 있던 forward 코드를 MyView를 통해 한 곳에 통일해 모든 컨트롤러에서 중복을 제거하고 경로만 MyView로 반환하면 되서 코드가 깔끔해 졌다.  
* 이제 컨트롤러는 경로만 반환하면 된다. 

#### 동작 흐름
```
클라이언트가 /front-controller/v2/members/new-form 요청하면

URI를 가지고 URI에 맞는 값을 호출 하여 참조값을 저장
String requestURI = request.getRequestURI();
ControllerV2 controller = controllerMap.get(requestURI);

해당 참조값 컨트롤러를 호출하고 경로가 있는 MyView 객체를 만들고 반환한다.
MyView view = controller.process(request, response);

MyView 객체의 render 메서드를 호출하고 forward를 통해 JSP에게 요청, 응답 객체 를 전달한다.
view.render(request,response);
 응답할때 응답 객체에 HTML 을 담고 클라이언트에게 전달 한다. 
```
