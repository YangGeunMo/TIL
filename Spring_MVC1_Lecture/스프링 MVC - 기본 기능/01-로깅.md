# 로깅 

- 운영 시스템에서는 System.out.rpnitln()같은 시스템 콘솔을 사용하지 않고 별도의 로킹 라이브러리를 이용해 로그를 출력한다.

## 로깅 라이브러리
- 스프링 부트 라이브러리(spring-boot-starter-logging)가 함께 포함되어 있다.
  - SLF4J - http://www.slf4j.org
  - Logback - http://logback.qos.ch

- 로그 라이브러리는 Logback, Log4J, Log4J2 등등 많은데 통합해서 인터페이스로 제공하는 것이 SLF4J 라이브러리이다.
- 실무에서는 Logback을 대부분 사용한다.


## 로그 선언
- private final Logger log = LoggerFactory.getLogger(getClass());
- @Slf4j : 롬복 사용

### 로그 컨트롤러

~~~java
@Slf4j
@RestController
public class LogTestController {

    //private final Logger log = LoggerFactory.getLogger(getClass());


    @RequestMapping("/log-test")
    public String logTest() {
        String name = "Spring";

        System.out.println("name = " + name);
        

        log.trace("trace log={}", name);
        log.debug("debug log={}", name);
        log.info("info log={}", name);
        log.warn("warn log={}", name);
        log.error("error log={}", name);

        //로그를 사용하지 않아도 a+b 계산 로직이 먼저 실행됨, 이런 방식으로 사용하면 X
        log.debug("String concat log=" + name);
        return "ok";
    }
}
~~~

## 메핑 정보
- @RestController
  - @Controller는 반환값이 String이면 뷰 이름으로 인식되고 그 뷰를 찾고 뷰가 랜더링된다.
  - @RestController는 반환값이 뷰를 찾는게 아닌 HTTP 메시지 바디에 바로 입력된다.
  - @ResponseBody와 관련 있다.

## 테스트
- 로그가 추력되는 포멧 확인
  - 시간, 로그 레벨, 프로세스 ID, 쓰레드 명, 클래스명, 로그 메시지
- 로그 레벨 설정
  - LEVEL : TRACE -> DEBUG -> INFO -> WARN -> ERROR
  - 개발 서버는 DEBUG 출럭
  - 운영 서버는 INFO 출력
- @Slf4j로 변경해서 사용하기

## 로그 메시지 설정 
- application.properties에서 설정
- 로그 레벨을 설정하면 그 레벨부터 로그가 나온다. 

~~~
#전체 로그 레벨 설정(기본 info)
logging.level.root=info

#hello.springmvc 패키지와 그 하위 로그 레벨
logging.level.hello.springmvc=debug
~~~

## 로그 사용법
- log.debug("data="+data)은 올바르지 않은 사용법
  - 로그 출력을 INFO로 설정해도 debug 코드가 실행되어 버린다. 결과적으로 INFO부터 출력인데도 필요없는 작업을 한다.
- log.debug("data={}", data)은 올바른 사용법
  - 로그 출력 레벨을 INFO로하면 아무 일도 발생하지 않는다. 의미없는 작업이 발생하지 않는다.
 
## 로그 사용시 장점
- 쓰레드 정보, 클래스 이름 등 부가 정보를 함께 볼 수 있고 출력 모양을 조정할 수 있다.
- 로그 레벨에 따라 상황에 맞게 설정할 수 있다. 예시) 개발 서버는 모든 로그 출력, 운영 서버는 출력하지 안는다 등
- 로그를 시스템 콘솔에만 출력하는게 아닌 파일이나 네트워크 등 별도의 위치에 저장 가능하다.
- 성능도 일반 System.out보다 성능이 좋다.(내부 버퍼링, 멀티 쓰레드 등)
