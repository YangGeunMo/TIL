# 요청 매핑 

~~~Java
//HTTP 메시지 바디에 바로 입력
@RestController
public class MappingController {

    private Logger log = LoggerFactory.getLogger(getClass());

    //이 url이 호출되면 메서드 실행
    @RequestMapping(value = "/hello-basic")
    public String helloBasic() {
        log.info("helloBasic");
        return "ok";
    }
~~~
## HTTP 메서드
- @RequestMapping에 method 속성으로 HTTP를 지정하지 않으면 HTTP 메서드가 모두 허용한다. GET, POST, HEAD, PUT, PATCH, DELETE 모두 호출 가능하다. 

## 매핑 정보
- @Controller는 반환값이 String으로 뷰 이름을 인식한다. 그리고 뷰를 찾고 뷰가 랜더링 된다.
- @RequestController는 HTTP 메시지 바디에 바로 입력한다.
- @RequestMapping은 URL 호출이 오면 메서드가 실되도록 매핑한다.

## HTTP 메서드 매핑
~~~java
@RequestMapping(value = "/mapping-get-v1", method = RequestMethod.GET)
  public String mappingGetV1() {
    log.info("mappingGetV1");
    return "ok";
}
~~~

- method 속성을 이용해 특정 HTTP메서드만 사용할 수 있다.
  - method = RequestMethod.GET : GET만 허용
  - POST로 요청하면 스프링 MVC는 HTTP 405 상태코드 반환

## HTTP 메서드 매핑 축약
~~~java
    @GetMapping(value = "/mapping-get-v2")
    public String mappingGetV2() {
        log.info("mapping-get-v2");
        return "ok";
    }
~~~

-  HTTP 메서드를 축양한 어노테이션을 사용하는게 더 직관적이다. 코드 내부를 보면 @RequestMapping과 method를 지정해서 사용한다.

### @GetMapping 코드 내부
~~~java
@RequestMapping(method = RequestMethod.GET)
public @interface GetMapping {
~~~

## PathVariable(경로 변수) 사용
~~~java
    @GetMapping("/mapping/{userId}")
    public String mappingPath(@PathVariable String userId) {
        log.info("mappingPath userId={}", userId);
        return "ok";
    }
~~~

- HTTP API는 리소스 경로에 식별자를 넣는 스타일을 선호한다.
  - /mapping/userA
    - 로그 결과 : mappingPath userId=userA
- @RequestMapping은 URL 경로를 템플릿화할 수 있다. ({userId} 등)
  
- @PathVariable을 사용하면 URL 경로의 변수 부분({userId})에서 
  실제 값을 추출해서 메서드 매개변수로 받을 수 있다.
  
- 예: /user/{userId} 에서 요청 /user/john 이 오면 @PathVariable로 userId = "john" 을 추출
  
- PathVariable의 이름과 파라미터 이름이 같으면 생량 가능하다.
  - @PathVariable("userId") String data -> @PathVariable String userId

## PathVariable 사용 - 다중
~~~java
  @GetMapping("/mapping/users/{userId}/orders/{orderId}")
    public String mappingPath(@PathVariable String userId, @PathVariable Long
            orderId) {
        log.info("mappingPath userId={}, orderId={}", userId, orderId);
        return "ok";
    }
~~~

## 특정 파라미터 조건 매핑
~~~java
    @GetMapping(value = "/mapping-param", params = "mode=debug")
    public String mappingParam() {
        log.info("mappingParam");
        return "ok";
    }
~~~
- 특정 파라미터가 있거나 조건을 추가해 실행된다.
- /mapping-param?mode=debug
  - mode=debug없을경우 실행이 안된다.
- 잘 사용하지 않는다.

## 특정 헤더 조건 매핑
~~~java
    @GetMapping(value = "/mapping-header", headers = "mode=debug")
    public String mappingHeader() {
        log.info("mappingHeader");
        return "ok";
    }
~~~
- 파라미터 조건 매핑과 비슷하다. HTTP 헤더를 사용한다.
- 쿼리 파라미터 조건과 HTTP 헤더 조건이 맞아야 실행된다.

## 미디어 타입 조건 매핑 - HTTP 요청 Content-Type, consume
~~~java
    @PostMapping(value = "/mapping-consume", consumes = "application/json")
    public String mappingConsumes() {
        log.info("mappingConsumes");
        return "ok";
    }
~~~
예시
~~~
consumes = "text/plain"
consumes = {"text/plain", "application/*"}
consumes = MediaType.TEXT_PLAIN_VALUE
~~~

- HTTP 요청의 Content-Type 헤더를 기반으로 미디어 타입으로 매핑한다.
- 맞지 않으면 HTTP 415 상태코드를 반환한다.

## 미디어 타입 조건 매핑 - HTTP 요청 Accept, produce
~~~java
  @PostMapping(value = "/mapping-produce", produces = "text/html")
    public String mappingProduces() {
        log.info("mappingProduces");
        return "ok";
    }
~~~

- 클라이언트가 Accept: text/html을 요청했을 때만 실행
- produces : 응답 형식을 text/html 형식으로만 응답을 보낸다.
