# 서블릿

# 스프링 부트 서블릿 환경 구성

## `@ServletComponentScan`
스프링 부트는 서블릿을 등록해서 사용할 수 있다.

```
@ServletComponentScan //서블릿 자동 등록
@SpringBootApplication
public class ServletApplication {

	public static void main(String[] args) {	
		SpringApplication.run(ServletApplication.class, args);
	}
}
```

## @WebServlet 
* 서플릿 애노테이션
* name : 서블릿 이름
* urlPatterns: URL 매핑

```
@WebServlet(name = "helloServlet", urlPatterns = "/hello")
```

HTTP 요청으로 매핑된 URL이 호출 되면 서블렛 컨테이너는 service 메서드를 실행한다.
```
protected void service(HttpServletRequest request, HttpServletResponse response)
```

service 메서드를 실행하면서 HTTP 요청 데이터를 읽을 수 있고 HTTP 응답 데이터를 작성할 수 있다.

# HttpServletRequest

HttpServletRequest 역할
* HTTP 요청 메시지를 개발자가 직접 파싱해서 사용하면 매우 불펴하다.
* 서블릿은 요청 메시지를 개발자 대신 파싱해준다. (편리하게 사용할 수 있다)
* 파싱한 데이터를  HttpServletRequest 객체에 담아 제공해준다. 

HTTP 요청 메시지
```
POST /save HTTP/1.1
Host: localhost:8080
Content-Type: application/x-www-form-urlencoded

username=kim&age=20
```
이러한 요청이 있을때 이러한 내용을 조회할 수 있다. 
* START LINE :HTTP 메서드, URL, 쿼리 스트링, 스키마, 프로토콜
* 헤더 : 헤더 조회
* 바디 : form 파라미터 형식 조회, message body 데이터 직접 조회

임시 저장소 기능이 있다. 해당 HTTP 요청이 시작부터 끝날 떄까지 유지된다.
- 저장: `request.setAttribute(name, value)`
- 조회: `request.getAttribute(name)`

세션 관리 기능
* `request.getSession(create: true)`


# HTTP 요청 데이터 
HTTP 요청 메시지를 통해 클라이언트 서버에서 서버로 전달하는 방법


## GET - 쿼리 파라미터 
전달 데이터
* username=hello
* age=20

메시지 바디 없이 URL의 쿼리 파라미터를 사용해 데이터를 전달한다. 
예시) 검색, 필터, 페이징 등에서 많이 사용하는 방식

쿼리 파라미터는 ?시작으로 보낼 수 있고 추가 파라미터는 &로 구분한다.
* http://localhost:8080/request-param?username=hello&age=20

### 쿼리 파라미터 조회 메서드
```
//단일 파라미터 조회 
String username = request.getParameter("username"); 
//파라미터 이름 모두 조회
Enumeration<String> parameterNames = request.getParameterNames(); 
//복수 파라미터 조회
String[] usernames = request.getParameterValues("username"); 
```

### 파라미터 이름은 하나인데 값이 중복인 경우
* request.getParameter() 는 하나의 파라미터 이름에 대해서 하나의 값만 있을 때 사용해야한다. 중복일때 사용하면 첫번째 값만 반환한다.
* 중복일 경우 request.getParameterValues() 사용

## POST HTML Form
<img width="560" height="40" alt="image 3" src="https://github.com/user-attachments/assets/cb702815-6071-468b-9a87-f46193a9af05" />

회원가입, 상품 주문 등에서 사용하는 방식

- content-type:`application/x-www-form-urlencoded`
- 메시지 바디에 쿼리 파리미터 형식으로 데이터를 전달한다. `username=hello&age=20`

POST의 HTML Form을 전송하면 웹 브라우저는 HTTP 메시지를 만든다.(개발자 모드에서 확인 가능)
- content-type: `application/x-www-form-urlencoded`
- message body: `username=hello&age=20`

- application/x-www-form-urlencoded 형식은 GET 쿼리 파라미터 형식과 같아서 쿼리 파라미터 조회 메서드를 그대로 사용할 수 있다. 
- request.getParameter()는 GET 쿼리 파라미터, POST HTML Form 형식 둘다 지원한다. 


### GET - 쿼리 파라미터와 POST HTML Form 차이

GET - 쿼리 파라미터는 HTTP body를 사용하지 않기에 content -type이 필요없다.
POST HTML Form은 데이터를 전달할때 HTTP body에 데이터를 담아서 보내기 때문에 content-type을 꼭 지정해야한다. 

## API 메시지 바디 - 단순 텍스트
HTTP message body에 데이터를 담아 요청한다. 
* HTTP API에서 주로 사용한다 (JSON, XML, TEXT)
* 주로 JSON을 사용한다.
* POST,PUT, PATCH
HTTP 메시지 바디의 데이터를 InputStream을 사용해서 읽을 수 있다. 
```
ServletInputStream inputStream = request.getInputStream();
String messageBody = StreamUtils.copyToString(inputStream,StandardCharsets.UTF_8);
```

* inputStream은 바이트코드를 반환하기에 String으로 보려면 문자표를 지정해야 한다. 
* Postman으로 실행
  * POST http://localhost:8080/request-body-string
  * content-type: text/plain
  * message body: `hello`
  * 결과: `messageBody = hello`

## API 메시지 바디 - JSON

```
// ObjectMapper는 JSON을 자바 객체로 변환해주는 도구
private ObjectMapper objectMapper = new ObjectMapper();

@Override
protected void service(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {

    // HTTP 요청 본문(body)을 입력 스트림으로 가져온다
    ServletInputStream inputStream = request.getInputStream();

    // 입력 스트림의 데이터를 UTF-8 문자열로 변환한다
    String messageBody = StreamUtils.copyToString(inputStream, StandardCharsets.UTF_8);

    System.out.println("messageBody = " + messageBody);
    
    // JSON 문자열을 파싱해서 HelloData 객체로 변환한다
    HelloData helloData = objectMapper.readValue(messageBody, HelloData.class);

    // 파싱된 데이터에서 username과 age를 출력한다
    System.out.println("helloData.username = " + helloData.getUsername());
    System.out.println("helloData.age = " + helloData.getAge());
    
    // 클라이언트에게 응답을 보낸다
    response.getWriter().write("ok");
}
```

JSON결과를 파싱해서 사용하려면 Jackson, Gson같은 JSON 변환 라이브러리를 사용해야한다. 스프링 부트로 Spring MVC를 선택하면 Jackson 라이브러리 ObjectMapper를 사용할 수 있다. 


Postman으로 실행
message body:`{"username": "hello", "age": 20}` 요청하면
출력결과
```
messageBody={"username": "hello", "age": 20}
data.username=hello
data.age=20
```
# HTTP 응답 데이터

## HttpServletResponse 

HttpServletResponse의 역할
- HTTP 응답 메시지 생성 
  - HTTP 응답 코드
  - 헤더 생성
  - 바디 생성

편의 기능
* Content-Type
* 쿠키
* Redirect

HTTP 응답 코드
```
response.setStatus(HttpServletResponse.SC_OK); //200
```

쿠키 
```
Cookie cookie = new Cookie("myCookie", "good");
cookie.setMaxAge(600); //600초
response.addCookie(cookie);
```

redirect
```
response.sendRedirect("/basic/hello-form.html");// 설정한 경로로 이동한다. 
```

### HTML 응답
```
//Content-Type: text/html;charset=utf-8
response.setContentType("text/html");
response.setCharacterEncoding("utf-8");
```

HTTP 응답으로 HTML을 반환할때는 content-type을 text/html 지정해야 하낟. 


### API JSON 응답
```
// JSON을 자바 객체로 변환하는 도구
private ObjectMapper objectMapper = new ObjectMapper();

@Override
protected void service(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {

    // HTTP 요청 본문을 입력 스트림으로 가져온다
    ServletInputStream inputStream = request.getInputStream();

    // 입력 스트림을 UTF-8 문자열로 변환한다
    String messageBody = StreamUtils.copyToString(inputStream, StandardCharsets.UTF_8);

    System.out.println("messageBody = " + messageBody);
    
    // JSON 문자열을 HelloData 객체로 변환한다 (파싱)
    HelloData helloData = objectMapper.readValue(messageBody, HelloData.class);

    // 변환된 객체의 데이터를 출력한다
    System.out.println("helloData.username = " + helloData.getUsername());
    System.out.println("helloData.age = " + helloData.getAge());
    
    // 응답을 보낸다
    response.getWriter().write("ok");
}
```

JSON으로 반환할때는 content-type을 application/json으로 지정해야 한다.
Jackson 라이브러리가 제공하는 objectMapper.writeValueAsString()을 사용하면 객체를 JSON문자로 변경 가능하다. 

application/json은 utf-8을 사용하도록 정의 되어 있다. 그래서 charset=utf-8을 추가하는건 의미 없다.
